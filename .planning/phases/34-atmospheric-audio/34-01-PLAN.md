# Plan 34-01: Atmospheric Audio Generation & Provider Integrity

## Objective
Harden atmospheric soundscape generation across Stable Audio 2 and ACE-Step 1.5 providers. Eliminate silent synthetic fallback in production mode, provide clear and honest status indicators in the user interface, validate audio payloads, and ensure durable scene association and playback after project reload.

## Tasks
1. Audit and Harden Backend Audio Providers:
   - Update `backend/app/providers/media/ace_step.py`:
     - Fix endpoint URL to modern Hugging Face router conventions (`https://router.huggingface.co/models/facebook/musicgen-small`).
     - Detect HTTP 401/403/503 and return actionable provider unavailable errors indicating `HF_TOKEN` requirement.
   - Update `backend/app/providers/media/stable_audio.py`:
     - Maintain strict handling of official Stability AI API endpoints, detecting 401 (invalid key), 402 (insufficient credits), and 429 (rate limits).
   - Update `backend/app/providers/media/composite_audio.py`:
     - In real production mode (`ENVIRONMENT != 'demo'`), fail honestly with descriptive `ProviderUnavailableError` if credentials are unconfigured.
     - In demo/offline mode, return synthetic tones marked explicitly with `is_synthetic: True` and `provider_label: "Synthetic Preview"`.
2. Enhance Frontend Audio Display & Status:
   - Update `MediaPreviewCard.tsx` and `AtmosphereDeck.tsx`:
     - Differentiate real live generation (`[Live Stable Audio 2]`, `[Live ACE-Step 1.5]`) from synthetic previews (`[Synthetic Preview]`).
     - Provide informative status and tooltip explaining external API credential requirements when providers are unconfigured.
3. Verification & Testing:
   - Add/update pytest tests in `backend/tests/test_audio_generation.py` for honest error handling, credential validation, and metadata persistence.
   - Verify that real generated or stored audio persists, associates to scenes, and plays seamlessly across project reloads.
