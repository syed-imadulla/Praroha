# Phase 10 Plan 1 (10-01-PLAN.md): Backend Divergent Worlds Engine

## Goal
Implement the backend data models, DB migration columns, AI provider extensions (incorporating archetypes, 4-metric exploration profiles, and Seed Potential accepted/rejected bridges), and updated REST endpoints, validated with a dedicated Pytest suite.

---

## Requirements Addressed
- **DIV-01**: Synthesize exactly three intentional exploration archetypes (`familiar`, `radical`, `inverse`).
- **DIV-02**: Provide an AI-generated Exploration Profile across 4 metrics (Seed Fidelity, Novelty, Conceptual Distance, Feasibility: 0–100%) and a concise profile summary.
- **DIV-03**: Incorporate accepted Seed Potential items as positive generation pillars, exclude rejected items as negative constraints, and output emphasized potential labels.

---

## Proposed Changes

### 1. Data Models (`backend/app/models/world.py`)
- Define `DivergenceArchetype(str, Enum)` with values `familiar`, `radical`, `inverse`.
- Define `ExplorationProfile(BaseModel)` with:
  - `seed_fidelity: int = Field(default=80, ge=0, le=100)`
  - `novelty: int = Field(default=70, ge=0, le=100)`
  - `conceptual_distance: int = Field(default=50, ge=0, le=100)`
  - `feasibility: int = Field(default=80, ge=0, le=100)`
  - `summary: str = Field(default="Balanced exploration profile")`
- Extend `WorldCandidate`:
  - `divergence_archetype: DivergenceArchetype = DivergenceArchetype.familiar`
  - `exploration_profile: ExplorationProfile = PydanticField(default_factory=ExplorationProfile)`
  - `emphasized_potential_labels: List[str] = PydanticField(default_factory=list)`
- Extend `WorldCandidateBase` and `WorldCandidateRecord`:
  - `divergence_archetype: str = Field(default="familiar")`
  - `exploration_profile: Optional[Dict[str, Any]] = Field(default=None, sa_column=Column(JSON, nullable=True))`
  - `emphasized_potential_labels: Optional[List[str]] = Field(default=None, sa_column=Column(JSON, nullable=True))`
- Update `WorldCandidateRecord.to_candidate()` and `WorldCandidateRecord.to_read_schema()` to populate these fields with backward-compatible defaults.
- Extend `WorldCandidateRead` with:
  - `divergence_archetype: str = "familiar"`
  - `exploration_profile: ExplorationProfile = PydanticField(default_factory=ExplorationProfile)`
  - `emphasized_potential_labels: List[str] = PydanticField(default_factory=list)`

### 2. Repository Layer (`backend/app/repositories/project_repo.py`)
- In `_migrate_columns`:
  - Add schema migration for `divergence_archetype`, `exploration_profile`, and `emphasized_potential_labels` on `world_candidates`.
- In `save_world_candidates`:
  - Extract and store `divergence_archetype`, `exploration_profile`, and `emphasized_potential_labels` from incoming candidates.

### 3. AI Providers
- `backend/app/providers/base.py`:
  - Update `generate_worlds(dna: Dict[str, Any], potential_items: Optional[List[Dict[str, Any]]] = None) -> List[Dict[str, Any]]`.
- `backend/app/providers/mock_provider.py`:
  - Update `CANONICAL_WORLDS` fixtures with explicit divergence archetypes (`familiar`, `radical`, `inverse`), canonical exploration profiles, and emphasized potential item labels.
  - Implement heuristic divergence generation for arbitrary seeds:
    - Candidate 1: `familiar` (high fidelity, low distance)
    - Candidate 2: `radical` (high novelty, high distance)
    - Candidate 3: `inverse` (extreme distance, subversive tension)
    - Distribute accepted potential items across candidates as emphasized labels.
- `backend/app/providers/gemini_provider.py`:
  - Update system prompt with instructions on synthesizing the Familiar / Radical / Inverse triad.
  - Inject accepted potential items as mandatory pillars and rejected items as negative constraints into prompt contents.
  - Update Gemini `generationConfig.responseSchema` to include `divergence_archetype`, `exploration_profile`, and `emphasized_potential_labels`.
  - Maintain graceful fallback to `MockProvider` on network errors, schema parse errors, or missing API keys.

### 4. Router (`backend/app/routers/worlds.py`)
- In `generate_world_candidates`:
  - Fetch stored potential items for the project via `repo.get_potential_items(project_id)`.
  - Pass potential items list into `ai_provider.generate_worlds(dna_dict, potential_items=potential_items)`.

### 5. Automated Tests (`backend/tests/test_divergence.py`)
- Test `ExplorationProfile` and `DivergenceArchetype` schema validation and constraint bounds (0–100).
- Test `MockProvider.generate_worlds` with canonical demo seed returns all 3 distinct archetypes and valid exploration profiles.
- Test `MockProvider.generate_worlds` with arbitrary seed and potential items (accepted items reflected in `emphasized_potential_labels`).
- Test `GeminiProvider.generate_worlds` fallback returns valid divergence metadata.
- Test endpoint `POST /api/projects/{id}/worlds/generate` returns valid divergence archetypes, exploration profiles, and emphasized potential labels.
- Test backward-compatibility when reading older candidates lacking exploration profiles.
