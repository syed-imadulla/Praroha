# Phase 20: Plan 2 (20-02-PLAN.md) — Frontend Creator Lock Controls & Visual Indicators
**Status:** Completed ✅

## Wave 2: Frontend Creator Lock Controls (Stage 4 Human-Only Zones Panel, Stage 5 Pre-Unfold Banner, Codex Lock Indicators & Playwright E2E Suite)

### Goal
Implement the frontend user experience for **Human-Only Zones (HOZ)** (`HOZ-01`, `HOZ-02`), empowering creators to define and lock their Core Theme, Protagonist Motivation, and Central Conflict before universe expansion begins. The interface features a dedicated **Human-Only Zones Panel** (`#human-only-zones-panel`) in Stage 4 with visual padlock toggles and 1-click smart suggestions, an **Active Creator Locks Banner** in Stage 5 prior to unfolding, prominent `CREATOR LOCKED` indicator tags on affected character and scene cards, synchronized `HUMAN_DECISION` badges in the Origin Ledger and Causal Lineage DAG, production build validation, and a comprehensive Playwright E2E verification suite.

---

### Scope Boundaries & Non-Goals
- **Strictly in Scope**:
  - TypeScript types: `HumanOnlyZones` interface, updated `DecisionDNA` and `WorldSelectionCreate` in `frontend/src/types/index.ts`.
  - Store integration: `humanOnlyZones` state slice, `setHumanOnlyZones`, and selection synchronization in `frontend/src/store/workspaceStore.ts`.
  - Stage 4 UI: `#human-only-zones-panel` in `frontend/src/components/SelectionCanvas.tsx` with 3 dedicated inputs, lock toggles, and auto-suggest actions.
  - Stage 5 UI: Active Human-Only Zones banner and `CREATOR LOCKED` card badges in `frontend/src/components/UniverseCodexCanvas.tsx`.
  - "Why is this here?" explainer modal updates in `frontend/src/components/WhyIsThisHereModal.tsx` for Human-Only Zone citations.
  - Production build verification (`npm run build --prefix frontend`).
  - End-to-end Playwright automation script (`frontend/e2e/test_phase20_human_only_zones.cjs`) capturing visual artifacts.
- **Strictly Out of Scope**:
  - Rewriting existing media generation panels or mutation canvas.
  - Phase-breaking changes to Stage 1–3 components.

#### 2. Stage 4 Human-Only Zones Panel & Lock Semantics
- **Files**:
  - `frontend/src/components/SelectionCanvas.tsx`
- **Responsibilities**:
  - Build `#human-only-zones-panel`:
    - Styled with amber/gold accents (`border-amber-500/40`, `bg-amber-950/20`), padlock icons (`Lock` / `Unlock` from lucide-react), and clear explainer badge: `"HUMAN-ONLY ZONES: INVIOLABLE CREATIVE AXIOMS"`.
    - 3 dedicated inputs:
      - Core Theme (`#hoz-input-theme`)
      - Protagonist Motivation (`#hoz-input-motivation`)
      - Central Conflict (`#hoz-input-conflict`)
    - **Lock Semantics**:
      - While unlocked (`is_locked: false`), creator can freely type, edit, and clear inputs.
      - Clicking "Lock Parameters" (`#hoz-lock-toggle-btn`) sets `is_locked = true` and freezes inputs into a readonly state with glowing amber lock badges.
      - **"Suggest from Selected World"** button (`#hoz-suggest-btn`): Populates suggested text based on selected world archetype and Seed DNA into the inputs as **unlocked draft suggestions only**. AI suggestions are never automatically locked or treated as human decisions; the creator must review and explicitly click "Lock Parameters" to claim them.
      - Only locked parameters are transmitted to the backend as immutable Human-Only Zones.
