# Phase 48: Dedicated Worker Architecture & Local Prototype Plan

## Phase Goal
Audit existing job models and dispatch mechanisms, author a minimal standalone worker container definition (`Dockerfile.worker`), implement the worker CLI runner (`backend/app/workers/cinematic_worker.py`), and verify end-to-end rendering and storage upload locally using existing assets with zero paid API calls and zero web server overhead.

---

## Architecture Contract & Scope

```mermaid
graph TD
    CLI[Worker CLI Entrypoint: cinematic_worker.py] -->|1. Load Job Spec| JobModel[(GenerationJob / Spec)]
    CLI -->|2. Read Local/Storage Assets| Assets[Concept Art PNG + Edge-TTS MP3 + Ambient WAV]
    CLI -->|3. Subprocess Execution| FFmpeg[Isolated FFmpeg Subprocess]
    FFmpeg -->|4. Render 720p H.264 MP4| LocalTmp[/tmp/render_scratch.mp4]
    CLI -->|5. Upload Output| Storage[SupabaseStorageProvider / Local Fallback]
    CLI -->|6. Update Status & Metadata| DB[(PostgreSQL / SQLite)]
```

## Verification & Acceptance Criteria
1. **Zero Web Impact**: Worker container runs as a batch CLI script with no open HTTP ports.
2. **Deterministic Output**: Generates valid 720p H.264 MP4 with synchronized dialogue and ducked audio in < 5 seconds locally.
3. **Storage Handshake**: Successfully writes to Supabase Storage (or local storage fallback) and updates database record.
4. **Honest Badging**: Output metadata strictly contains `is_synthetic: true` and `provider_label: "Cinematic Preview"`.
5. **Zero Paid Calls**: 100% of testing executes on existing local fixtures without external model spend.
