# Phase 13 Plan 2 (13-02-PLAN.md): Frontend Media Architecture & E2E Suite

## Goal
Implement frontend TypeScript models, API client bindings, and Zustand workspace store integrations for asynchronous media jobs, build a reusable `MediaPreviewCard` component with loading skeletons and native media playback, and create an automated Playwright E2E test suite validating non-blocking generation and deterministic mock playback.

---

## Requirements Addressed
- **MED-01**: Abstract `MediaProvider` base interfaces consumed through typed client bindings.
- **MED-02**: Verifiable mock media assets rendered natively in the frontend (SVG graphics, WAV audio).
- **MED-03**: Strictly asynchronous, non-blocking generation with loading skeletons, status polling, and error recovery.

---

## Technical Tasks

### 1. Frontend Types (`frontend/src/types/index.ts`)
- Add media type declarations:
  ```typescript
  export type MediaType = 'image' | 'voice' | 'video' | 'audio';
  export type MediaJobStatus = 'queued' | 'processing' | 'completed' | 'failed';

  export interface MediaAsset {
    id: string;
    project_id: string;
    entity_type: 'world' | 'character' | 'location' | 'scene';
    entity_id: string;
    media_type: MediaType;
    status: MediaJobStatus;
    asset_url?: string | null;
    mime_type?: string | null;
    prompt: string;
    provider_name: string;
    error_message?: string | null;
    created_at: string;
    completed_at?: string | null;
  }

  export interface MediaGenerationRequest {
    entity_type: 'world' | 'character' | 'location' | 'scene';
    entity_id: string;
    media_type: MediaType;
    prompt: string;
    aspect_ratio?: string;
    voice_id?: string;
    duration_sec?: number;
    mood?: string;
    context?: Record<string, any>;
  }

  export interface MediaJobResponse {
    job_id: string;
    status: MediaJobStatus;
    media_type: MediaType;
    entity_id: string;
    asset_url?: string | null;
    error_message?: string | null;
  }
  ```

### 2. API Client Integration (`frontend/src/api/client.ts`)
- Add methods to `apiClient`:
  - `generateMedia(projectId: string, req: MediaGenerationRequest): Promise<ApiResponse<MediaJobResponse>>`
  - `getMediaJob(projectId: string, jobId: string): Promise<ApiResponse<MediaJobResponse>>`
  - `getMediaAssets(projectId: string, entityId?: string, mediaType?: MediaType): Promise<ApiResponse<MediaAsset[]>>`
  - `getMediaProvidersHealth(): Promise<ApiResponse<Record<string, any>>>`

### 3. Workspace Store Actions (`frontend/src/store/workspaceStore.ts`)
- Add state properties:
  - `mediaAssets: Record<string, MediaAsset[]>` (keyed by `entity_id`)
  - `activeMediaJobs: Record<string, MediaJobResponse>` (keyed by `job_id`)
- Add actions:
  - `requestMediaGeneration(entityType, entityId, mediaType, prompt, options)`: dispatches generation and starts background polling without blocking UI state.
  - `fetchMediaAssets(projectId, entityId?)`: loads stored media assets.
  - `pollMediaJob(jobId, projectId)`: polls job endpoint every 500ms until status is `completed` or `failed`.

### 4. Reusable Media Preview Card (`frontend/src/components/MediaPreviewCard.tsx`)
- Implement `MediaPreviewCard`:
  - **Queued / Processing State**: Renders smooth animated pulsing shimmer skeleton with modal icon and status indicator (`Generating visual/voice...`).
  - **Completed State**:
    - `image`: Displays responsive `<img>` with zoom modal on click.
    - `voice` / `audio`: Displays styled HTML5 `<audio controls>` player with custom progress bar and volume controls.
    - `video`: Displays HTML5 `<video controls playsInline>` player.
  - **Failed State**: Renders error alert pill with descriptive error message and an interactive `Retry` button.

### 5. Automated Playwright E2E Suite (`frontend/e2e/test_phase13_media_provider.cjs`)
- Implement comprehensive automated browser verification:
  - **Scenario 1**: Verify Provider Health endpoint returns operational status for all 4 modalities.
  - **Scenario 2**: Dispatch mock image generation for a character card, verify non-blocking loading skeleton, and verify completed SVG render.
  - **Scenario 3**: Dispatch mock voice generation, verify status transitions from `processing` to `completed`, and verify native audio player.
  - **Scenario 4**: Verify persistence: reloading the page preserves generated media asset attachments.
  - **Scenario 5**: Simulate provider failure and verify graceful error notification without application crash.
