## Wave 1: Backend Counterfactual Replay Engine (Candidate Extraction, Hybrid Delta Calculation, AI Semantic Projection & Isolated Branching)

### Goal
Implement the complete backend Counterfactual Replay subsystem (`CNTR-01`, `CNTR-02`), enabling creators to inspect structured divergence deltas between their currently selected world and rejected candidate worlds without full universe re-generation. The subsystem features candidate extraction from the project's selection batch, instant deterministic baseline comparison, on-demand AI semantic delta projection across 4 dimensions (Protagonist, Tone & Atmosphere, Central Conflict, Lore & Rules), exploration profile comparison, zero-destruction timeline branching rooted in the alternative candidate via `PersistenceService.branch_project`, project-level counterfactual metadata persistence, parent canon immutability, and a comprehensive pytest test suite.

---

### Scope Boundaries & Non-Goals
- **Strictly in Scope**:
  - Identifying rejected candidates from the project's Stage 3 generation batch.
  - Instant deterministic baseline comparison (comparing schemas, archetypes, and exploration profiles).
  - On-demand AI semantic delta projection with deterministic mock fallback (zero CoT leakage).
  - Exploration profile comparative metrics across Seed Fidelity, Novelty, Conceptual Distance, Feasibility.
  - Zero-destruction branching with deep parent immutability and complete child ID remapping.
  - Project-level `counterfactual_metadata_json` column and persistence.
  - API endpoints for candidate listing, delta computation, and branch forking.
- **Strictly Out of Scope**:
  - Phase 20 Human-Only Zones.
  - Automatic full universe re-generation (Bible, Characters, Scenes) for all 3 candidates simultaneously.
  - Three-way cross-branch timeline merging or cherry-picking.
  - New graph database or microservices.

#### 2. Implement Counterfactual Replay Service
- **File**: `backend/app/services/counterfactual_service.py`
- **Responsibilities**:
  - `get_counterfactual_candidates(project_id: str) -> List[CounterfactualCandidateRead]`:
    - Retrieves active world selection (`repo.get_active_world_selection`).
    - Retrieves all candidates for the batch (`repo.get_latest_world_candidates`).
    - Filters out the selected candidate, returning the 2 rejected worlds.
    - Attaches inferred exclusions derived from Decision DNA or candidate archetype.
  - `generate_counterfactual_delta(project_id: str, candidate_id: str, use_ai: bool = True) -> CounterfactualDeltaResponse`:
    - Retrieves canon candidate + active unfolded universe snapshot (lead character, physical law, primary conflict scene).
    - Retrieves target counterfactual candidate record.
    - Assembles instant deterministic baseline:
      - Exploration profile comparison with arithmetic deltas.
      - Protagonist, tone, conflict, and lore comparisons based on stored candidate fields and universe entities.
    - If `use_ai` and AI provider available:
      - Formulates a targeted prompt for semantic delta projection (hypothetical lead character shift, emotional atmosphere contrast, central tension divergence, physical rule alterations).
      - Handles timeouts, rate limits, and errors by gracefully falling back to deterministic synthesis.
      - Enforces zero Chain-of-Thought leakage in user-facing delta text.
    - Generates sanitized `suggested_branch_name` (e.g. `counterfactual/sunken-time-capsule`).
  - `fork_counterfactual_branch(project_id: str, req: ForkCounterfactualRequest) -> ProjectRead`:
    - Validates target candidate exists.
    - Calls `PersistenceService.branch_project` to clone project with fresh UUIDs and ID remapping.
    - In child branch:
      - Updates or creates `WorldSelectionRecord` pointing to `candidate_id`.
      - Persists `counterfactual_metadata_json` on child `ProjectRecord`.
      - Sets project status to `world_selected` so creator can unfold it.
    - Asserts parent project remains 100% immutable and unchanged.
    - Returns child `ProjectRead`.
