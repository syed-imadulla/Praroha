# Phase 49: Azure Container Apps Job Pilot & Cloud Benchmarking Plan

## Phase Goal
Provision an on-demand Azure Container Apps Job running the native worker image, execute bounded cloud rendering tests (< 30 runs) against existing PRAROHA world assets, empirically measure real render duration, memory, CPU, and cost against the ₹500 budget, and verify failure isolation, job deduplication, and crash recovery.

---

## Architecture Contract & Scope

```mermaid
graph TD
    CLI[Azure CLI: az containerapp job start] --> Controller[ACA Job Controller]
    Controller -->|Spin Up On-Demand Container (1.0 vCPU, 2.0 GiB)| WorkerInstance[ACA Job Worker Instance]
    WorkerInstance -->|Fetch Source Assets| SupaStorage[(Supabase Storage: seed-unfold-assets)]
    WorkerInstance -->|Compose MP4| FFmpeg[Native FFmpeg]
    WorkerInstance -->|Upload Rendered MP4| SupaStorage
    WorkerInstance -->|Update Job Record| SupaDB[(Supabase PostgreSQL)]
    WorkerInstance -->|Exit Code 0| Terminate[Scale to 0 Replicas Immediately]
```

## Detailed Task Breakdown

### Wave 1: Cloud Job Configuration & Provisioning
- [ ] **TASK-49-01**: Author Azure CLI deployment script for `az containerapp job create`:
  - Name: `praroha-cinematic-preview-job`
  - Trigger type: `manual` (on-demand API dispatch)
  - Resources: `1.0` vCPU, `2.0` GiB RAM
  - Replica timeout: `120` seconds
  - Concurrency: `parallelism=1`, `replicaCompletionCount=1`
  - Secrets: Ingest `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_KEY` securely from ACA environment.
- [ ] **TASK-49-02**: Build and push `Dockerfile.worker` to ACR (`praroha-preview-worker:latest`).

### Wave 2: Cloud Execution Benchmarking & Cost Audit
- [ ] **TASK-49-03**: Trigger single-run test job with canonical world asset paths; measure cold-start latency, render duration, and output file size.
- [ ] **TASK-49-04**: Verify generated MP4 uploads to Supabase Storage bucket `seed-unfold-assets` with valid public HTTPS URL.
- [ ] **TASK-49-05**: Check Azure Portal Cost Analysis to measure actual compute charges, confirming execution falls within the free tier allowance or costs < ₹0.05 per render.

### Wave 3: Failure Modes, Deduplication & Crash Recovery
- [ ] **TASK-49-06**: Verify request deduplication via `request_hash`; ensure identical preview requests reuse existing assets without launching duplicate ACA Jobs.
- [ ] **TASK-49-07**: Test failure handling and timeout guard: simulate job with invalid input, confirming worker exits with error code, updates job to `failed`, and frees memory without hanging.
- [ ] **TASK-49-08**: Verify orphaned job recovery: confirm stale jobs (>180s) are safely transitioned to `failed` upon startup/reconciliation.

---

## Verification & Acceptance Criteria
1. **Cloud Execution**: Genuine 720p H.264 MP4 rendered on Azure infrastructure and persisted to Supabase Storage.
2. **Budget Compliance**: Cumulative test spend verified under ₹50.00 (well below the ₹500 ceiling).
3. **Primary App Immunity**: Zero CPU or memory spikes observed on the primary `praroha-backend` web service.
4. **Lifecycle Integrity**: Container job terminates cleanly and scales to 0 replicas upon completion.
