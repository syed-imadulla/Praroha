# Phase 31.11: Final Judging Readiness — Provider Reliability, End-to-End Fixes & Release Freeze

## Objective
Establish complete judging readiness for PRAROHA. Make every feature work reliably with its real configured provider, fix actual integration failures (specifically Pollinations image generation HTTP 402, Edge-TTS synthesis, Stability Audio protocol, and media lifecycle), verify real asset generation and persistence, and validate the full user journey across 1440px, 1024px, and 390px viewports.

---

## Execution Phases

### Phase 1 — Audit the Complete Provider Architecture
- Search codebase for all providers, endpoints, environment variables, and fallback chains.
- Audit Pollinations, Edge-TTS, Stability AI, Hugging Face/ACE-Step, Gemini Imagen 3, Gemini Flash text generation, and any custom endpoints.
- Document exact contracts, auth methods, payload formats, timeouts, rate limits, and output formats.

### Phase 2 — Fix Pollinations Image Generation
- Investigate the HTTP 402 Payment Required error reported previously on Pollinations.
- Check official Pollinations API endpoints (`image.pollinations.ai` vs `pollinations.ai/p/` vs `enter.pollinations.ai`), API key support (`POLLINATIONS_API_KEY`), model query parameters (`flux`, `turbo`, `seed`), and headers (`Authorization: Bearer`).
- Implement robust error handling (distinguish 401/402 payment/auth from transient network errors) and provide graceful, explicit fallback to Gemini Imagen 3 when configured.
- Test real scene concept image generation, verify image decoding, DB persistence, and frontend rendering.

### Phase 3 — Make Edge-TTS Reliable
- Confirm `edge-tts` package and version in `backend/requirements.txt`.
- Verify supported voices (`en-US-GuyNeural`, `en-US-AriaNeural`, `en-GB-SoniaNeural`, etc.) with sensible default and fallback.
- Enforce non-empty MP3 audio bytes, duration parsing, and concurrency isolation so simultaneous voice jobs don't collide.
- Test real Character Voice and Scene Narration synthesis.

### Phase 4 — Fix Stability AI Stable Audio
- Ensure `backend/app/providers/media/stable_audio.py` uses the canonical synchronous HTTP 200 flow for Stable Audio 2 (`/v2beta/audio/stable-audio-2/text-to-audio`).
- Validate duration clamping (5-190s), multipart form data, and specific HTTP 401/402/429 exception handling.
- Verify test coverage and document live generation status as BLOCKED if funded credits are absent.

### Phase 5 — Fix Hugging Face / ACE-Step & Other Audio Providers
- Validate Hugging Face endpoint handling and confirm serverless inference limitations for `facebook/musicgen-small`.
- Validate binary audio signatures (MP3, WAV, FLAC, OGG) and preserve distinction between speech and ambient music.

### Phase 6 — Build One Reliable Media Generation Pipeline
- Inspect `MediaService`, generation jobs table, and Supabase storage upload.
- Ensure idempotent job retries, duplicate prevention, cross-project isolation, and Supabase Realtime broadcast.
- Ensure frontend retry buttons trigger actual job resubmission.

### Phase 7 — Verify All Other AI Features
- Test Seed DNA extraction, 3-world synthesis, world locking, universe unfolding (World Bible, Characters, Relationships, Scenes), and lineage DAG.
- Verify schema adherence, JSON error recovery, and continuity exports.

### Phase 8 — Visual & Responsive Quality
- Inspect Character and Dynamics cards across 1440px (Desktop), 1024px (Tablet), and 390px (Mobile).
- Check padding, typography, button placement, media players, and botanical design compliance.
- Capture and inspect fresh browser screenshots.

### Phase 9 — Real Provider Smoke Tests & Full Regression
- Build a dedicated provider smoke test tool/command.
- Run unit test suite (`pytest backend/tests/test_audio_generation.py`, `test_media_provider.py`, etc.).
- Run full backend suite (`pytest backend/tests`).
- Run frontend production build (`npm run build`).
- Run full autonomous E2E browser journey (`test_phase31_10_journey.mjs`) and dual-tab realtime test (`test_phase31_10_realtime.mjs`).

### Phase 10 — Final Judging Readiness & Release Freeze
- Audit environment variables, secret hygiene (no leaked keys in frontend or git), and storage permissions.
- Compile final judging report: VERIFIED, BLOCKED, FAILED, Provider Matrix, and Release Decision.
