# Phase 14 Plan 1 (14-01-PLAN.md): Backend Image Provider Engine

## Goal
Implement the concrete **Image Generation Provider Engine** (`IMG-01`), including `PollinationsImageProvider` (primary keyless cloud generator with transient retry and exponential backoff), `FluxSchnellProvider` (local inference fallback), a 3-tier fallback orchestrator (`Pollinations` $\rightarrow$ `Flux` $\rightarrow$ `Mock`), prompt enrichment with universe `SeedDNA` visual context, persistent image metadata tracking (`width`, `height`, `aspect_ratio`, resolved provider, timestamps) (`IMG-02`), and a comprehensive Pytest test suite with explicit multi-tier fallback and retry-exhaustion verification.

---

## Requirements Addressed
- **IMG-01**: Concrete `PollinationsProvider` as primary image generator (world covers, character portraits, scene visuals) where usable free/team path is available; with local FLUX.1 schnell fallback where practical, and `MockMediaProvider` as fallback of last resort.
- **IMG-02**: Generated image assets are stored via `StorageProvider` (Supabase Storage / local uploads) with metadata tracking.

---

## Technical Tasks

### 1. Concrete Pollinations Image Provider with Retry & Backoff (`backend/app/providers/media/pollinations.py`)
- Implement `PollinationsImageProvider(ImageProvider)`:
  - Base URL: `https://image.pollinations.ai/prompt/{encoded_prompt}`
  - Dynamic resolution based on `aspect_ratio`:
    - `1:1`: $1024 \times 1024$
    - `16:9`: $1280 \times 720$
    - `9:16`: $720 \times 1280$
  - Query parameters:
    - `width`, `height`, `model="flux"`, `seed`, `nologo=true`
  - Client configuration:
    - Configurable timeout (default 25.0s, configurable via `POLLINATIONS_TIMEOUT_SEC`).
    - Uses `httpx.AsyncClient(timeout=timeout, follow_redirects=True)`.
  - **Locked Retry & Exponential Backoff Behavior**:
    - Retries transient HTTP 429 (rate limit) responses.
    - Retries transient HTTP 5xx (500, 502, 503, 504) responses.
    - Retries network timeouts / connectivity failures where appropriate.
    - Exponential backoff schedule using pure `asyncio.sleep` (e.g., initial backoff 1.0s, multiplier 2.0x, max 2 retries).
    - Only after retry exhaustion does the provider raise `ProviderUnavailableError` to allow cascade to the next tier.
  - On success:
    - Parses binary response (`image/jpeg` or `image/png`).
    - Returns `MediaPayload(data=..., mime_type=..., filename=..., metadata={"width": w, "height": h, "aspect_ratio": ar, "resolved_provider": "pollinations"})`.
  - Implements `health_check()`.

### 2. Local FLUX.1 schnell Provider (`backend/app/providers/media/flux.py`)
- Implement `FluxSchnellProvider(ImageProvider)`:
  - Checks if `FLUX_ENDPOINT` environment variable is configured (e.g. local ComfyUI/Diffusers microservice).
  - If unset or unreachable, raises `ProviderUnavailableError` allowing immediate cascade to Tier 3 mock.
  - If configured and reachable, dispatches image generation POST request with prompt and dimensions.
  - On success:
    - Returns `MediaPayload(data=..., mime_type=..., filename=..., metadata={"width": w, "height": h, "aspect_ratio": ar, "resolved_provider": "flux"})`.
  - Implements `health_check()`.

### 3. 3-Tier Composite Image Provider (`backend/app/providers/media/composite.py`)
- Implement `CompositeImageProvider(ImageProvider)`:
  - Encapsulates:
    - Tier 1: `PollinationsImageProvider`
    - Tier 2: `FluxSchnellProvider`
    - Tier 3: `MockImageProvider` (guaranteed safe final fallback)
  - `generate_image()` execution flow:
    1. Attempts Tier 1 (`Pollinations`) with retry/backoff.
    2. On retry exhaustion or network failure, attempts Tier 2 (`Flux`).
    3. On Tier 2 failure, cleanly falls back to Tier 3 (`MockImageProvider`).
  - Error containment:
    - Client never receives an unhandled 500 error for provider failure.
    - Mock is the guaranteed final fallback.
    - `MediaPayload.metadata["resolved_provider"]` accurately records the provider that actually synthesized the asset (`"pollinations"`, `"flux"`, or `"mock"`).
  - Implements composite `health_check()`.

### 4. Context-Aware Visual Prompt Enrichment (`backend/app/services/media_service.py`)
- Update `MediaService`:
  - When generating images, fetches project `SeedDNA` via `repo.get_seed_dna(project_id)`.
  - Enriches raw prompt with aesthetic consistency framing:
    - Tone cue: `Tone: {dna.tone}`
    - Style cues: `Style: {', '.join(dna.domain_keywords[:3])}`
    - Atmosphere: `Atmosphere: {dna.themes[:2]}`
  - Prepends aesthetic context while preserving the author's core prompt intact.
  - Enriched prompt is passed to the provider and saved in the database record.

### 5. Image Metadata Relational Persistence (`backend/app/models/media.py` & `project_repo.py`)
- Extend media models in `backend/app/models/media.py`:
  - Add explicit image metadata fields to `MediaAssetBase`, `MediaAssetRecord`, and `MediaAssetRead`:
    - `width: Optional[int] = Field(default=None, nullable=True)`
    - `height: Optional[int] = Field(default=None, nullable=True)`
    - `aspect_ratio: Optional[str] = Field(default="1:1", nullable=True)`
    - `metadata_json: Optional[str] = Field(default="{}", nullable=True)`
- Update database schema migration in `backend/app/repositories/project_repo.py`:
  - In `_migrate_columns`: add non-destructive column additions for `width`, `height`, `aspect_ratio`, `metadata_json` on table `media_assets`.
- Update `MediaService._run_generation_pipeline`:
  - Persists image metadata for every generated asset:
    - `width`, `height`, `aspect_ratio`
    - `provider_name`: resolved provider from `MediaPayload.metadata["resolved_provider"]`
    - `prompt`: enriched prompt
    - `asset_url`: storage upload URL
    - `mime_type`: MIME type
    - `created_at`, `completed_at`
    - `metadata_json`: serialized JSON containing entity context, original raw prompt, and model details.

### 6. Media Factory Configuration (`backend/app/providers/media/factory.py`)
- Update `MediaProviderFactory.get_image_provider()`:
  - Resolves `CompositeImageProvider` by default when `IMAGE_PROVIDER` is unset or set to `pollinations`.
  - Resolves `MockImageProvider` when `IMAGE_PROVIDER=mock`.

### 7. Pytest Verification Suite (`backend/tests/test_image_generation.py`)
- Implement comprehensive test suite:
  1. `test_pollinations_url_and_parameters`: Verifies dimensions mapping (`1:1` $\rightarrow$ 1024x1024, `16:9` $\rightarrow$ 1280x720, `9:16` $\rightarrow$ 720x1280), seed derivation, and query parameters.
  2. `test_pollinations_retry_and_backoff_transient_recovery`: Simulates a transient 503 or 429 response followed by a 200 response; verifies retry succeeds without falling back.
  3. `test_pollinations_retry_exhaustion_cascades_to_fallback`: Simulates persistent network/5xx failures; verifies fallback to Tier 2/3 occurs only after retry exhaustion.
  4. `test_3_tier_fallback_pollinations_fail_flux_success`: Simulates Pollinations failure $\rightarrow$ Flux succeeds $\rightarrow$ asserts `resolved_provider == "flux"` and payload is valid.
  5. `test_3_tier_fallback_pollinations_and_flux_fail_mock_success`: Simulates Pollinations and Flux failure $\rightarrow$ Mock succeeds $\rightarrow$ asserts `resolved_provider == "mock"`, SVG payload returned, and no 500 error raised.
  6. `test_prompt_enrichment_with_seed_dna`: Asserts Seed DNA tone, atmosphere, and visual keywords are included in prompt without corrupting original text.
  7. `test_image_metadata_persistence`: Generates image and verifies database record preserves `width`, `height`, `aspect_ratio`, `provider_name`, `metadata_json`, `prompt`, `completed_at`.
  8. `test_image_api_with_aspect_ratios`: Verifies REST API invocation with aspect ratios (`1:1`, `16:9`, `9:16`).
  9. Full regression run: verifies all 86 existing tests continue to pass.
