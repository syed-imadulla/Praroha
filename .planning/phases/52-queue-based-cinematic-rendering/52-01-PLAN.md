# Phase 52: Queue-Based Cinematic Rendering Architecture Plan

## Phase Goal
Implement and verify a scale-to-zero, event-driven queue dispatch architecture for PRAROHA cinematic preview generation. The solution eliminates all network ingress from the worker container, guarantees transactional message dispatch, enforces strict idempotency and poison message handling, isolates rendering workloads in a dedicated standard Azure Container Apps environment (`env-praroha-render`), preserves the public backend in `env-tendersaathi` without disruption, and operates strictly within the ₹500 budget limit (< ₹50 target).

---

```mermaid

    User([Creator in Browser]) -->|Click 'Generate Cinematic Preview'| UI[EntityMediaSection Component]

        API -->|4. Return HTTP 202 Accepted| UI
    end
    
    subgraph NEW Standard Managed Environment: env-praroha-render (ConsumptionOnly - ₹0 Base Fee)
        Queue -->|Event Trigger: queueLength >= 1| KEDA[KEDA azure-queue Scaler]
        KEDA -->|Spawn Ephemeral Execution| Job[Container Apps Job: praroha-render-job]
        
        Job -.->|Zero Ingress: No Ports / No Listeners| Internet([Blocked External Access])
        Job -->|Atomic Claim: UPDATE status='processing'| DB
        Job -->|Download Stems & Native FFmpeg Render| Scratch[Ephemeral /tmp Scratchpad]
        Job -->|Upload 720p MP4| Storage[Supabase Storage: seed-unfold-assets]
        Job -->|Finalize status='completed' & honest metadata| DB
        Job -->|Delete Message| Queue
        
        Job -.->|Exceeded 3 Retries| PoisonQueue[Dead-Letter Queue: cinematic-render-poison]
    end
    
    UI -->|Poll or Realtime Sync| API
```

## Verification & Acceptance Criteria

1. **Worker Isolation**: The worker container has **zero** open network ports, no web server dependencies, and is unreachable via HTTP.
2. **Scale-to-Zero Verification**: When no rendering jobs are queued, `praroha-render-job` has 0 running instances and incurs ₹0 compute charges.
3. **Environment Separation**: Public web API remains untouched in `env-tendersaathi`; batch rendering executes strictly in `env-praroha-render`.
4. **Transactional Delivery**: No render request is lost due to a crash between database write and queue insertion.
5. **Idempotency & Deduplication**: Repeated clicks with identical parameters return the existing active job without duplicate rendering. Failed jobs allow immediate clean retry.
6. **Poison Message Quarantine**: Malformed payloads or un-renderable inputs are moved to `cinematic-render-poison` after 3 attempts without blocking the work queue.
7. **Strict Financial Compliance**: Total pilot execution spend does not exceed ₹50 INR (10% of the ₹500 authorized cap).
