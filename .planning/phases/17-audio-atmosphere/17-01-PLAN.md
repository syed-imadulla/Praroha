# Phase 17: Plan 1 (17-01-PLAN.md) — Backend Audio & Atmosphere Engine

## Wave 1: Backend Audio Engine (ACE-Step 1.5, Stable Audio Open, Mock & Cascading Composite)

### Goal
Implement the complete backend Audio & Atmosphere generation subsystem featuring a 3-tier fallback hierarchy (`ACEStepAudioProvider` $\rightarrow$ `StableAudioOpenProvider` $\rightarrow$ `MockAudioProvider`), canonical acoustic prompt derivation, curated mood profiles, isolated response normalization, metadata persistence, and full pytest regression coverage.

---

### Tasks

#### 1. Implement Concrete ACE-Step 1.5 Audio Provider
- **File**: `backend/app/providers/media/ace_step.py`
- **Responsibilities**:
  - Implement `ACEStepAudioProvider(AudioProvider)`.
  - Configurable via `ACE_STEP_ENDPOINT` (or HuggingFace Inference API).
  - 30-second timeout, transient HTTP retries (3 attempts with exponential backoff), and structured outage simulation via `context.get("simulate_acestep_unavailable")`.
  - **MIME Type Preservation**:
    - Inspects HTTP `Content-Type` header and binary magic numbers to determine actual MIME type (`audio/wav` vs `audio/mpeg`).
    - Does NOT unconditionally hardcode `audio/wav`; never labels MP3 bytes as WAV.
    - Normalizes response into `MediaPayload(data=..., mime_type=actual_mime, filename=..., metadata={...})`. Never leaks external vendor structures.

#### 2. Implement Concrete Stable Audio Open Provider
- **File**: `backend/app/providers/media/stable_audio.py`
- **Responsibilities**:
  - Implement `StableAudioOpenProvider(AudioProvider)`.
  - Configurable via `STABLE_AUDIO_ENDPOINT` with standardized parameter mapping (`prompt`, `mood`, `duration_sec`).
  - Supports 30-second timeout and outage simulation via `context.get("simulate_stableaudio_unavailable")`.
  - Normalizes external vendor output strictly into standard `MediaPayload`, preserving actual supported MIME type (`audio/wav` or `audio/mpeg`).

#### 3. Standardize Deterministic Mock Audio Provider
- **File**: `backend/app/providers/media/mock.py`
- **Responsibilities**:
  - Ensure `MockAudioProvider` returns authentic, browser-playable WAV bytes using `_generate_wav_bytes` with harmonic chord structures per mood.
  - Persist standardized metadata: `resolved_provider="mock"`, `mood=mood`, `duration_sec=duration_sec`, `mime_type="audio/wav"`.

#### 4. Implement 3-Tier Cascading Composite Audio Provider
- **File**: `backend/app/providers/media/composite_audio.py`
- **Responsibilities**:
  - Implement `CompositeAudioProvider(AudioProvider)`.
  - Cascades: Tier 1 (`ACEStepAudioProvider`) $\rightarrow$ Tier 2 (`StableAudioOpenProvider`) $\rightarrow$ Tier 3 (`MockAudioProvider`).
  - Catches transient network errors, timeouts, or simulated outages, logging tier failures and cascading seamlessly.
  - Enforces response isolation: unifies output metadata (`resolved_provider`, `mood`, `duration_sec`) while preserving actual payload `mime_type`.

#### 5. Wire Factory & Modality Exports
- **Files**:
  - `backend/app/providers/media/factory.py`
  - `backend/app/providers/media/__init__.py`
- **Responsibilities**:
  - Update `MediaProviderFactory.get_audio_provider()`: returns `CompositeAudioProvider()` by default, and `MockAudioProvider()` when `AUDIO_PROVIDER=mock`.
  - Export new providers in `__init__.py`.

#### 6. Canonical Acoustic Prompt & Mood Derivation in Media Service
- **File**: `backend/app/services/media_service.py`
- **Responsibilities**:
  - In `MediaService.process_job_now`:
    - Preserves explicit creator prompts without modification.
    - If prompt is empty string, derives canonical audio prompt based on entity type:
      - **World**: `"{world.title} ambient soundscape. Atmosphere: {world.aesthetic}. {mood_descriptors}. Drone frequencies, textured organic background resonance, immersive 3D acoustic field."`
      - **Scene**: `"Scene atmosphere: {scene.title} in {scene.location_setting}. Tone: {mood}. Dramatic environmental underscore, thematic instrumentation, cinematic background score."`
    - Handles `mood` parameter (defaulting to `"ambient"` or entity-suggested mood) and `duration_sec` (defaulting to 15).

#### 7. Backend Pytest Suite & Regression Verification
- **File**: `backend/tests/test_audio_generation.py`
- **Tests**:
  1. `test_mock_wav_audio_container_structure`: Validates binary RIFF/WAVE header, audio format, and sample rate.
  2. `test_ace_step_parameters_and_url`: Validates ACE-Step payload formatting, headers, and endpoint resolution.
  3. `test_ace_step_retry_and_timeout`: Validates timeout handling and exponential backoff.
  4. `test_stable_audio_provider_parameters`: Validates Stable Audio Open parameter mapping.
  5. `test_3_tier_fallback_acestep_fail_stableaudio_success`: Validates Tier 1 $\rightarrow$ Tier 2 cascade.
  6. `test_3_tier_fallback_acestep_and_stableaudio_fail_mock_success`: Validates Tier 1 $\rightarrow$ Tier 2 $\rightarrow$ Tier 3 cascade.
  7. `test_3_tier_fallback_via_context_outage_simulation`: Validates non-blocking context outage triggers.
  8. `test_audio_provider_response_isolation_and_mime_preservation`: Validates normalization into `MediaPayload` without vendor leakage and proves actual provider MIME types (`audio/wav` $\rightarrow$ `.wav`, `audio/mpeg` $\rightarrow$ `.mp3`) are preserved, ensuring MP3 bytes are never labeled as WAV.
  9. `test_canonical_acoustic_prompt_and_mood_enrichment`: Validates World and Scene prompt derivation & mood mapping.
  10. `test_audio_metadata_persistence`: Validates persistence of `resolved_provider`, `mood`, and `duration_sec`.
  11. `test_audio_api_endpoints`: Validates REST endpoints (`/media/generate`, polling, listing).
- **Regression Check**: Run `./.venv/bin/pytest backend/tests/ -v` and verify all 114 existing tests + new Phase 17 tests pass with 0 failures.
